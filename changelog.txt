       "delete Downloads daily" active while the UI claimed the opposite.
       The apply now deletes both values and the [8] screen checks they are
       absent.
   [x] iGPU detection regex replaced. It matched discrete GPU names
       ("Radeon RX", "RTX"...) which both missed real dGPUs (TITAN, Tesla,
       Arc Pro) and flagged the integrated "Radeon RX Vega 11 Graphics" as
       discrete - exactly the population the feature targets. It now matches
       known integrated names (UHD Graphics / Iris / HD Graphics N /
       Vega N Graphics / Radeon(TM) Graphics) instead.
   [x] Cleanup summary no longer counts the Downloads wipe as "Discord
       cache". The Downloads deletion ran between the two space-delta
       measurements, so its size was attributed to Discord. A dedicated

   [x] Verification screen [8]: removed two permanent false FAILs - the
       IFEO "%%~E" checks (a loop variable used outside any loop, so they
       read a nonexistent key) and the Start_Layout check (a value the
       script never writes). QCAM (camera choice) was read back but never
       checked - a FrameServer service check now uses it.
   [~] Restore [5] now refreshes the session (UpdatePerUserSystemParameters)
       like the apply does, so restored visuals reappear without waiting for
       the next sign-in.
   [~] The "Ultimate Performance" power plan is no longer duplicated in Soft
       mode or on a laptop - a ghost plan stayed in the power options for
       nothing on those paths.
   [x] Accessibility "Animation effects" is no longer silently turned off.
       On LIGHTFX the script wrote UserPreferencesMask = 9012038010000000,
       which clears bit 0x02 of byte 4 - the exact bit behind Settings >
       Accessibility > Visual effects > "Animation effects". The toggle
       flipped to off without ever being mentioned. The mask is now
       9012038012000000 (bit kept), and MinAnimate / TaskbarAnimations are
       written as 1 instead of 0 so the toggle and the actual behaviour
       agree. The [8] check for MinAnimate was updated to match.
       Verified by letting Windows itself flip the toggle through
       SPI_SETCLIENTAREAANIMATION and diffing the resulting mask bytes.
   [x] Phantom device cleanup removed nothing. The filter was
       `Status -eq 'Unknown' -and Class -ne 'AudioEndpoint' -and Class -ne
       'MEDIA'` - but phantom devices are almost always exactly the audio and
       media endpoints left behind by unplugged USB DACs, headsets and
       webcams, so the two exclusions cancelled the whole feature out. The
       filter is now `Problem -eq 'CM_PROB_PHANTOM' -and Present -ne $true`,
       which is the real definition of a phantom device: registered in the
       PnP tree, not physically present. No class is excluded any more:
       audio endpoints and media devices are removed like the rest - they are
       precisely the ones that pile up (unplugged DACs, headsets, webcams).
       Applied at all three sites (apply [33], menu [3] counter, re-apply
       task payload).
    !  Safety: a disabled-but-connected device reports CM_PROB_DISABLED with
       Present = true, so it can never match the new filter. Verified on a
       live machine: 4 disabled devices, 0 of them matched.
   [x] Storage Sense never ran. The script configured StoragePolicy correctly
       but nothing ever triggered the assistant: the native Windows task
       (\Microsoft\Windows\DiskFootprint\StorageSense) has no trigger and is
       driven by automatic maintenance, which may not fire for days. The
       script now runs it once at the end of [41], and the re-apply task runs
       it at every logon - gated on StoragePolicy 01 = 1, so it stays a no-op
       if the user disabled Storage Sense afterwards.
   [-] The one-shot cleanup no longer wipes the Downloads folder. It used to
       delete everything in %USERPROFILE%\Downloads (files and subfolders) on
       every full run, skipping only when the script itself sat inside that
       folder. Downloads is user content: the script has no business deciding
       it is garbage, and a single mis-click cost real data. The step, its two
       labels, its skip branch and its summary line are gone. The cleanup now
       covers six categories: Temp, Discord cache, Steam cache, WinSxS,
       Windows.old, Recycle Bin.
   [x] Discord cache cleanup freed 0 MB every single run. The script emptied
       %LOCALAPPDATA%\Discord\Cache, which does not exist - Discord (the
       Electron app) keeps its cache under %APPDATA%\discord. Measured on a

   [-] Defender real-time protection is never disabled any more. In LOWEST

  v3.7.1 -   0.5 ms TIMER WATCHDOG HARDENED (Fable 5 review)
================================================================================
   [x] KILLER BUG: AbandonedMutexException. If the timer watchdog was killed
       while holding the Global\LowLatTimerRes05 mutex, the scheduler restart
       hit WaitOne(0) which THREW (abandoned mutex) instead of returning true;
       with SilentlyContinue that evaluated to null -> exit 0 (= success in the
       scheduler's eyes) -> RestartCount neutralized, watchdog dead until next
       boot. Now the abandoned mutex is caught and treated as acquisition.
   [x] Silent-zombie: if Add-Type fails 120x (AV / WDAC / AppLocker blocking
       in-memory compile), the script used to spin forever requesting nothing,
       silently. Now it exits 1 so the scheduler sees the failure and retries.
   [+] Observability: NtQueryTimerResolution logs the effective resolution and
       the state (held / released) to HKLM:\SOFTWARE\LowLatOptimizer so the
       timer can actually be VERIFIED (TimerCur, TimerState, TimerAbandoned).
   [x] Battery: BatteryFlag is a bitfield; the test was -ne 128 (brittle on the
       unknown/255 state). Now (BatteryFlag -band 128) -eq 0.
   [~] Wording: docs/README no longer claim the timer is "released" on battery.
       Accurate claim: the script stops REQUESTING 0.5 ms. Another process
       (Chrome, some games) can keep the global timer high regardless.
   i  GlobalTimerResolutionRequests=1 is STRICTLY required on Win11 (without it
       the SYSTEM process only gets 0.5 ms for itself; the game sees nothing).
       It is read at boot, so the guarantee holds after reboot but NOT during
       the install session before the first reboot. Do NOT remove this key.
